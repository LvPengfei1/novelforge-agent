# NovelForge-Agent 使用手册

本手册说明如何从零开始使用 NovelForge-Agent 项目框架进行长篇小说创作。

本手册内容由 袁锐钦 Ruiqin 提供，并已根据本仓库现有 `AGENTS.md` / `Claude.md` 原则文件整理适配。Codex 等支持 `AGENTS.md` 的工具读取 `AGENTS.md`；Claude 工作流可读取 `Claude.md`。两个文件应保持规则内容等价，允许文件名表述按工具适配。

---

## 一、项目定位

NovelForge-Agent 不是小说正文，而是一套**可复用的小说写作项目结构**。它解决长篇创作中的三个核心问题：

1. **设定散落**：写到后面忘了前面设定的细节。
2. **人物变化丢失**：角色经历了几十章后，性格、动机和关系变化没有被持续记录。
3. **伏笔和时间线难以维护**：埋下的伏笔忘了回收，时间线或人物状态出现矛盾。

核心理念：所有设定必须落文件，不依赖对话记忆。

---

## 二、三层资料模型

本仓库根目录是框架工程，不直接写正式小说。正式创作前，将 `templates/novel-project/` 复制为 `projects/<novel-slug>/`，并把根目录的 `AGENTS.md`、`Claude.md`、`AIGC_DETECTION_PRINCIPLES.md`、`NOVEL_REVIEW_PROTOCOL.md` 放入该小说实例根目录。

之后在 `projects/<novel-slug>/` 中使用下面的三层资料模型。`projects/` 默认不提交到 Git，便于继续提交框架优化。

```text
raw/          <- 原始资源层（只读，不改写）
novel/        <- 小说工程层（正文、草稿、过程文件）
llm-wiki/     <- 设定知识库（日常资料定位入口）
```

| 层级 | 用途 | 能否修改 |
|------|------|----------|
| `raw/` | 用户提供的原始资料、网页剪藏、参考文章、图片和导入材料 | 只读 |
| `novel/` | 正文草稿、章节成稿、写作过程文件和必要备份 | 可改写 |
| `llm-wiki/` | 设定、人物、主线、时间线、伏笔、状态和矛盾检查知识库 | 由 AI 维护 |

日常写作时，AI 优先从 `llm-wiki/` 定位资料；单章龙骨通过 `llm-wiki/wiki/outline.md` 链接到 `novel/03_plot/chapters/` 后按需读取。只有 wiki 缺失、互相矛盾、需要核对原始依据或需要核对正文时，才回查 `raw/` 或其他 `novel/` 文件。

## 三、标准阶段流程

默认流程：项目简报与架构批准 -> 章节输入白名单 -> 章节写作包 -> 全新写作子智能体 -> 全新审查子智能体 -> 主控整合 -> 章后同步 -> 健康检查。

初稿阶段先把正文写完；原创性与文本质量检查、关联文件同步、证据等级复核都在初稿完成后执行。证据等级按 `AGENTS.md` / `Claude.md` 的原则、当前实例资料和当前证据判断。

仓库的 `scripts/novelforge.py` 负责确定性部分：初始化项目、校验架构版本与批准状态、验证项目内相对路径、按显式白名单封包、锁定来源哈希，并分开生成写作与审稿任务。它不代替模型写作或整章审读。

用户明确批准架构并完成四份正本后，运行 `approve <小说实例> --confirmation "确认依据"`，把批准版本与文件哈希写入 `architecture-approval.json`。之后任一正本发生变化，`validate` 和 `prepare` 都会停止，直到用户重新确认；不能只保留“已批准”字样绕过。

## 四、从零开始的标准流程

### 阶段一：项目初始化

**目标**：把你的小说构想填入项目框架。

先在框架仓库运行：

```powershell
python scripts/novelforge.py init projects/<novel-slug>
```

命令会复制空模板、三份规则/研究文件和默认独立审稿协议；目标目录非空时不会覆盖。进入生成的小说实例后再填写资料。

#### 步骤 1：填写项目简报

编辑 `novel/00_project/brief.md`，填入基本信息：

```markdown
## 基本信息

- 小说名称：深渊回响
- 类型题材：都市悬疑
- 目标读者：成年读者，喜欢慢热推理
- 篇幅目标：30万字，约60章
- 叙事视角：第一人称，主角视角
- 文风基准：冷硬克制，短句为主，少用修辞
- 禁用内容或禁用写法：不写血腥猎奇，不写开挂式反转
```

你可以自己填写，也可以直接让 AI 帮你整理：

> **提示词**：
> 我想写一本都市悬疑小说，主角是退休刑警，围绕 20 年前悬案重新被翻开。帮我填写 `brief.md`，整理基本信息、一句话核心和三个核心看点。

#### 步骤 2：提供原始设定资料

把素材放进 `raw/` 目录。支持以下内容：

- 已有的世界观设定文档。
- 人物设定笔记。
- 大纲或章节规划。
- 灵感片段。
- 参考文章或网页剪藏。

如果你没有整理好的文档，也可以口头描述：

> **提示词**：
> 我来口述一下我的人物设定，你帮我整理到 `raw/` 里。主角叫陈卫国，55 岁，退休刑警，性格沉闷……

#### 步骤 3：设定摄入

提供资料后，让 AI 执行摄入：

> **提示词**：
> 请将 `raw/` 里的资料摄入到 `llm-wiki/`。提取所有人物、地点、组织、规则、主线、伏笔和写作限制，标注证据等级，更新对应 wiki 页面、分类主节点和必要的索引入口。

AI 应完成：

1. 将原始资料保存或登记到 `raw/`。
2. 提取人物、地点、组织、规则、事件、伏笔、主题和写作限制，并标注证据等级。
3. 创建或更新 `llm-wiki/wiki/` 下的相关页面。
4. 更新对应分类主节点；如索引入口或摘要变化，再更新 `llm-wiki/wiki/index.md`。
5. 追加 `llm-wiki/wiki/log.md`。
6. 更新 `llm-wiki/ingest-manifest.md`。

---

### 阶段二：正文写作

**目标**：逐章推进，每章写完同步维护设定。

#### 步骤 4：规划章节龙骨

每章写正文前，先建章节龙骨：

> **提示词**：
> 请根据当前 `llm-wiki/`，生成第一章的章节龙骨草案。必须包含章节功能、开章状态、本章目标、核心推进、结尾变化、后续约束和待回收问题。不要写正文。

AI 会读取 `llm-wiki/` 中的相关资料，生成一份龙骨草案写入 `novel/03_plot/chapters/ch001-spine.md`。你确认或修改后再进入正文写作。

#### 步骤 5：写正文

写正文前，AI 应先根据当前项目资料生成本章的临时内容执行标准、输入白名单和章节写作包。内容执行标准用于确认本章文风、读者期待、人物压力和章节阅读感；章节写作包只给本章全新写作子智能体使用，不放同步检查、主智能体推理、废案、日志或操作说明。

正式正文只能在架构获用户确认后生成。主智能体先建立本章输入白名单和章节写作包。全局正本固定包含当前有效的项目简报、全书龙骨、总体大纲和文风正本；人物、关系、时间线、伏笔、地点与规则只提取本章相关部分，并附必要的上一章结尾。

每个新章节启动一个全新的写作子智能体。它不继承主对话，不复用上一章写作者，不自行搜索全库，只读取白名单和章节写作包。正文完成后，再启动另一个全新审查子智能体；审查者读取同一版本的全局正本、本章包、必要的前章结尾和正文，不读取写作者的推理或自评。

将 `_chapter-job-template.json` 复制为本章任务文件，在 `chapter_sources` 中填写本章资料，在 `previous_excerpt` 中限定前章行号范围，在 `recent_chapters` 中填写最多三份只供审稿比较的材料。路径必须相对小说实例，归档、日志和运行目录不能作为输入。

```powershell
python <框架目录>/scripts/novelforge.py validate <小说实例> --job novel/03_plot/chapters/ch001-job.json
python <框架目录>/scripts/novelforge.py prepare <小说实例> --job novel/03_plot/chapters/ch001-job.json
```

第二条命令输出独立运行目录。只把其中 `writer-task.md` 的文本交给 `fork_context=false` 的全新写作子智能体；不要再补主对话或临时搜索结果。使用外部无状态模型命令时，可用 `invoke --stage writer -- <command>` 启动一个无 shell 的新进程。

`invoke` 只接受直接可执行程序，拒绝批处理入口和常见命令解释器，并在执行前重新核对当前 job、批准快照、来源与任务内容。无 shell 新进程不会自动限制该程序读取磁盘或访问网络；涉及私密资料时，应在受限工作区或容器中运行，NovelForge 的白名单只保证任务封包没有主动提供未声明文件。

> **提示词**：
> 请确认当前架构已经批准，并为第一章建立写作输入白名单和章节写作包。全局正本必须包含项目简报、全书龙骨、总体大纲和文风正本；本章包只包含相关人物状态、冲突、选择、代价、连续性事实和必要的前章结尾。不要写正文。

确认后再写正文：

> **提示词**：
> 请启动一个不继承主对话的全新写作子智能体，只向它提供第一章输入白名单和章节写作包，生成正文并写入 `novel/05_manuscript/ch001.md`。若资料不足，让子智能体返回缺口，不得自行全库搜索。

也可以提具体要求：

> **提示词**：
> 写第一章正文，3000 字左右。要求开场节奏快，前 500 字内必须建立紧张感。对话不超过全文 30%。

> **提示词**：
> 续写第一章正文，从上次停笔的地方接着写。注意保持陈卫国的冷硬语气，不要突然变温柔。

#### 步骤 6：章后同步

正文写完后，先启动一个与写作者不同的全新审查子智能体，完成整章读稿、最近三章结构比较和语言复查。故事动力、人物选择或场景因果未通过时退回重写；通过后再同步相关页面：

```powershell
python <框架目录>/scripts/novelforge.py prepare-review <小说实例> --run <运行目录>
```

该命令先核对写作时锁定的来源哈希，再生成 `reviewer-task.md`，同时锁定待审正文哈希。正文随后发生任何变化，旧审稿任务都会拒绝执行。审稿者只读取该任务，不读取写作者的推理、自评或主对话。外部无状态审稿命令可通过 `invoke --stage reviewer -- <command>` 单独启动。

> **提示词**：
> 第一章正文已完成。请按章节龙骨模板执行章后同步：质量检查、关联文件同步、节点缺口检查、分类主节点、必要索引入口和日志。

AI 应以 `novel/03_plot/chapters/_chapter-spine-template.md` 为准完成同步，至少覆盖：当前实例要求的验收项、原创性与文本质量检查、章节龙骨、全书龙骨、剧情总纲、时间线、人物/关系状态、伏笔、矛盾标记、节点缺口、分类主节点、必要索引入口和日志。

正文文件必须保持纯净，只包含章节标题和正文。章末变更记录、同步检查、修改原因、审查记录等内容应写入章节龙骨、连续性资料或 `llm-wiki/wiki/log.md`，不要写进正文文件。

注意：章节正文写完但同步检查未完成，不算真正完成该章。

---

### 阶段三：持续推进

#### 后续章节

重复步骤 4-6。每章开始前可以查询上下文：

> **提示词**：
> 请汇总与第二章相关的人物、地点、伏笔和未解决冲突。只列已确立事实，标出 wiki 缺失或矛盾的条目。

#### 批量推进多章

> **提示词**：
> 请生成第二、三、四章的章节龙骨草案。三章之间要有递进关系，第二章结尾必须引出第三章的核心冲突。

> **提示词**：
> 按第二、三、四章的龙骨依次推进。每一章都重新建立输入白名单，启动全新写作子智能体和全新审查子智能体；本章审查与同步完成后，才进入下一章。任何子智能体不得继承主对话或自行全库搜索。

## 六、核心规则速览

### 文件职责

| 文件 | 职责 |

### 优先级

1. 系统与开发者指令
2. 用户当前请求
3. `AGENTS.md` 或 `Claude.md` 项目原则
4. `docs/` 中的方案和流程
5. `llm-wiki/` 设定和资料
6. `novel/` 正文、草稿和备份资料
7. memory 或历史会话

### 关键原则

- **所有设定必须落文件**：不依赖对话记忆。
- **日常资料只走 `llm-wiki/`**：源文件只用于证据回查或正文核对。
- **每章必须维护龙骨**：未完成同步不算章节完成。
- **关联文件必须同步**：按章节龙骨模板和项目规则原则完成关联检查。
- **正文优先**：设定、资料、大纲都服务正文。
- **正文纯净**：正文文件只放章节标题和正文，工程化记录放到龙骨、连续性资料或日志。
- **上下文隔离**：每章使用全新写作实例；全局正本与本章白名单由主控提供，正文生成层不继承主对话，不搜索全库，也不接触废案、日志和内部流程。
- **画面优先**：少解释情绪，少替读者总结，允许人物和对白保留自然瑕疵。
- **原创性优先**：初稿后执行文本质量检查，问题正文必须修改复查。
- **默认向后推进**：前文回改须先确认影响范围。
- **`raw/` 只读**：原始资源不得修改。

## 七、典型工作流示例

### 场景 A：全新开始

```text
你：我想写一本修仙小说，主角是个废柴弟子，意外获得上古传承。
    帮我填写 brief.md，然后规划前五章的大纲。

AI：填写 brief.md -> 生成或登记 raw/ 设定 -> 摄入 llm-wiki -> 生成前五章龙骨。

你：确认第一章架构与龙骨后，启动全新写作子智能体写正文，4000 字，开场要有反差感。

AI：建立输入白名单与章节写作包 -> 启动不继承主对话的全新写作子智能体 -> 写正文到 ch001.md -> 启动另一个全新审查子智能体。

你：同步 llm-wiki。

AI：按章节龙骨模板完成质量检查、关联文件同步、节点缺口检查和日志记录。

你：继续写第二章。
```

### 场景 B：已有大纲，快速推进

```text
你：我已经把大纲文档放入 raw/。请摄入 raw/ 中的大纲，然后从第一章开始写。

AI：摄入 -> 生成龙骨 -> 写正文 -> 同步 -> 询问是否继续下一章。
```

### 场景 C：写到中途发现矛盾

```text
你：我发现第 8 章里主角说他不认识李某，但第 3 章里两人已经见过面了。
    帮我检查一下。

AI：检查 wiki -> 确认矛盾 -> 列出影响范围 -> 提出修正方案。

你：按方案 A 改，改完后同步。

AI：修改第 8 章正文 -> 更新受影响章节龙骨、人物状态、时间线、伏笔、矛盾标记、分类主节点和日志。
```

### 场景 D：隔一段时间回来继续写

```text
你：我上次写到第 15 章，帮我回顾一下当前进度。

AI：读取 book-spine.md、llm-wiki/wiki/outline.md、最新章节龙骨、log.md。
    当前主线在第 X 阶段，第 15 章结尾是……，未回收伏笔有 X 条，下一步应该……

你：继续写第 16 章。

AI：生成第 16 章龙骨 -> 确认 -> 写正文 -> 同步。
```

## 八、注意事项

1. **一章一龙骨**：不要跳过龙骨直接写正文，也不要写完正文再补龙骨。
2. **同步要及时**：正文完成后立即同步，不要攒着。
3. **不要一次塞太多**：AI 写作时只读取当前章节相关资料，不读全部文件。
4. **回改要谨慎**：修改前文前先确认影响范围，改完必须同步检查后续。
5. **口头确认的设定也要落文件**：对话中讨论确定的设定必须写入 `llm-wiki/`。
6. **证据等级要明确**：AI 推断不得写成已确立事实。
7. **先初稿后编辑**：不要在初稿过程中反复按检查项打断正文。
8. **定期健康检查**：每 5-10 章做一次 `llm-wiki` 健康检查，防止矛盾积累。
