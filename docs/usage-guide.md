# NovelForge-Agent 使用手册

本手册说明如何从零开始使用 NovelForge-Agent 项目框架进行长篇小说创作。

本手册内容由 袁锐钦 Ruiqin 提供，并已根据本仓库现有 `AGENTS.md` / `Claude.md` 规则文件整理适配。Codex 等支持 `AGENTS.md` 的工具读取 `AGENTS.md`；Claude 工作流可读取 `Claude.md`。两个文件应保持规则内容等价，允许文件名表述按工具适配。

---

## 一、项目定位

NovelForge-Agent 不是小说正文，而是一套**可复用的小说写作项目结构**。它解决长篇创作中的三个核心问题：

1. **设定散落**：写到后面忘了前面设定的细节。
2. **人物变化丢失**：角色经历了几十章后，性格、动机和关系变化没有被持续记录。
3. **伏笔和时间线难以维护**：埋下的伏笔忘了回收，时间线或人物状态出现矛盾。

核心理念：所有设定必须落文件，不依赖对话记忆。

---

## 二、三层资料模型

```text
raw/          <- 原始资源层（只读，不改写）
novel/        <- 小说工程层（正文、草稿、过程文件）
llm-wiki/     <- 设定知识库（日常唯一检索入口）
```

| 层级 | 用途 | 能否修改 |
|------|------|----------|
| `raw/` | 用户提供的原始资料、网页剪藏、参考文章、图片和导入材料 | 只读 |
| `novel/` | 正文草稿、章节成稿、写作过程文件和必要备份 | 可改写 |
| `llm-wiki/` | 设定、人物、主线、时间线、伏笔、状态和矛盾检查知识库 | 由 AI 维护 |

日常写作时，AI 优先从 `llm-wiki/` 定位资料；单章龙骨通过 `llm-wiki/wiki/outline.md` 链接到 `novel/03_plot/chapters/` 后按需读取。只有 wiki 缺失、互相矛盾、需要核对原始依据或需要核对正文时，才回查 `raw/` 或其他 `novel/` 文件。

## 三、从零开始的标准流程

### 阶段一：项目初始化

**目标**：把你的小说构想填入项目框架。

#### 步骤 1：填写项目简报

编辑 `novel/00_project/brief.md`，填入基本信息：

```markdown
## 基本信息

- 小说名称：深渊回响
- 类型题材：都市悬疑
- 目标读者：成年读者，喜欢慢热推理
- 篇幅目标：30万字，约60章
- 叙事视角：第一人称，主角视角
- 文风基准：冷硬克制，短句为主，少用修辞
- 禁用内容或禁用写法：不写血腥猎奇，不写开挂式反转
```

你可以自己填写，也可以直接让 AI 帮你整理：

> **提示词**：
> 我想写一本都市悬疑小说，主角是退休刑警，围绕 20 年前悬案重新被翻开。帮我填写 `brief.md`，整理基本信息、一句话核心和三个核心看点。

#### 步骤 2：提供原始设定资料

把素材放进 `raw/` 目录。支持以下内容：

- 已有的世界观设定文档。
- 人物设定笔记。
- 大纲或章节规划。
- 灵感片段。
- 参考文章或网页剪藏。

如果你没有整理好的文档，也可以口头描述：

> **提示词**：
> 我来口述一下我的人物设定，你帮我整理到 `raw/` 里。主角叫陈卫国，55 岁，退休刑警，性格沉闷……

#### 步骤 3：设定摄入

提供资料后，让 AI 执行摄入：

> **提示词**：
> 请将 `raw/` 里的资料摄入到 `llm-wiki/`。提取所有人物、地点、组织、规则、主线、伏笔和写作限制，更新对应 wiki 页面和索引。

AI 应完成：

1. 将原始资料保存或登记到 `raw/`。
2. 提取人物、地点、组织、规则、事件、伏笔、主题和写作限制。
3. 创建或更新 `llm-wiki/wiki/` 下的相关页面。
4. 更新对应分类主节点；仅在新增分类主节点时更新 `llm-wiki/wiki/index.md`。
5. 追加 `llm-wiki/wiki/log.md`。
6. 更新 `llm-wiki/ingest-manifest.md`。

---

### 阶段二：正文写作

**目标**：逐章推进，每章写完同步维护设定。

#### 步骤 4：规划章节龙骨

每章写正文前，先建章节龙骨：

> **提示词**：
> 请根据当前 `llm-wiki/`，生成第一章的章节龙骨草案。必须包含章节功能、开章状态、本章目标、核心推进、结尾变化、后续约束和待回收问题。不要写正文。

AI 会读取 `llm-wiki/` 中的相关资料，生成一份龙骨草案写入 `novel/03_plot/chapters/ch001-spine.md`。你确认或修改后再进入正文写作。

#### 步骤 5：写正文

> **提示词**：
> 请根据第一章龙骨写正文，写入 `novel/05_manuscript/ch001.md`。

也可以提具体要求：

> **提示词**：
> 写第一章正文，3000 字左右。要求开场节奏快，前 500 字内必须建立紧张感。对话不超过全文 30%。

> **提示词**：
> 续写第一章正文，从上次停笔的地方接着写。注意保持陈卫国的冷硬语气，不要突然变温柔。

#### 步骤 6：章后同步

正文写完后，AI 必须同步更新相关页面：

> **提示词**：
> 第一章正文已完成。请同步更新：章节龙骨、剧情总纲、全书龙骨、时间线、人物状态、关系状态、伏笔账本、矛盾标记、索引和日志。

AI 应按章节龙骨模板中的同步检查清单逐项处理：

- [ ] 已更新 `book-spine.md`
- [ ] 已更新 `llm-wiki/wiki/outline.md` 或确认无需更新
- [ ] 已更新 `timeline.md`
- [ ] 已更新 `character-states.md`
- [ ] 已更新 `relationship-states.md`
- [ ] 已更新 `foreshadowing-ledger.md`
- [ ] 已更新 `contradiction-flags.md` 或确认无矛盾
- [ ] 已完成原创性与 AIGC 痕迹质量检查
- [ ] 已执行节点缺口检查
- [ ] 已新建或更新触发建卡门槛的人物、地点、组织、规则、物品、重要场景和伏笔节点页
- [ ] 已更新对应分类主节点；仅在新增分类主节点时更新 `index.md`
- [ ] 已追加 `log.md`

注意：章节正文写完但同步检查未完成，不算真正完成该章。

---

### 阶段三：持续推进

#### 后续章节

重复步骤 4-6。每章开始前可以查询上下文：

> **提示词**：
> 请汇总与第二章相关的人物、地点、伏笔和未解决冲突。只列已确立事实，标出 wiki 缺失或矛盾的条目。

#### 批量推进多章

> **提示词**：
> 请生成第二、三、四章的章节龙骨草案。三章之间要有递进关系，第二章结尾必须引出第三章的核心冲突。

> **提示词**：
> 按第二、三、四章的龙骨依次写正文，每章写完后立即同步 `llm-wiki/`，再写下一章。

## 四、提示词速查

### 项目初始化

| 场景 | 提示词 |
|------|--------|
| 填写项目简报 | 帮我填写 `brief.md`，我的小说是…… |
| 口述设定 | 我来口述人物/世界观设定，帮我整理到 `raw/` 并摄入 `llm-wiki/`。 |
| 摄入已有文档 | 请将 `raw/` 里的资料摄入到 `llm-wiki/`，提取所有人物、地点、组织、规则、主线和伏笔。 |
| 补充新设定 | 新增一个人物：……请更新 `llm-wiki/` 相关页面。 |

### 写作前准备

| 场景 | 提示词 |
|------|--------|
| 生成章节龙骨 | 请根据 `llm-wiki/`，生成第 X 章的章节龙骨草案。 |
| 查询人物状态 | 请查询【人物名】的当前状态、核心动机、关系变化和禁止违背的写法。 |
| 查询场景上下文 | 请汇总与第 X 章相关的人物、地点、伏笔和未解决冲突。 |
| 查询地点信息 | 请查询【地点名】的功能、氛围、相关人物和已发生事件。 |
| 列出未回收伏笔 | 请列出当前所有未回收伏笔，按与第 X 章的相关度排序。 |

### 正文写作

| 场景 | 提示词 |
|------|--------|
| 按龙骨写正文 | 请根据第 X 章龙骨写正文，写入 `novel/05_manuscript/chXXX.md`。 |
| 带要求写正文 | 写第 X 章正文，3000 字左右，要求…… |
| 续写 | 续写第 X 章，从上次停笔的地方接着写。 |
| 改写某段 | 请改写第 X 章中【某个段落/场景】，改为……风格，注意保持与前后文一致。 |
| 润色 | 请润色第 X 章正文，保持文风不变，优化节奏和对话。 |

### 章后同步

| 场景 | 提示词 |
|------|--------|
| 完整同步 | 第 X 章正文已完成，请同步更新所有 `llm-wiki/` 页面。 |
| 局部同步 | 第 X 章新增了伏笔【内容】，请更新 `foreshadowing-ledger.md` 和伏笔分类主节点。 |
| 检查同步状态 | 请检查第 X 章的章节龙骨同步检查清单，看哪些项目还没完成。 |

### 连续性检查

| 场景 | 提示词 |
|------|--------|
| 检查章节一致性 | 请检查第 X 章龙骨是否与 `book-spine.md`、`timeline.md`、`character-states.md` 等页面一致。 |
| 检查场景矛盾 | 请检查第 X 章涉及的人物状态、时间线、道具是否存在矛盾。 |
| 全面健康检查 | 请执行 `llm-wiki` 健康检查：孤立页面、缺失页面、页面矛盾、过时设定。 |
| 查找重复设定 | 请找出可能重复的人物、地点、组织或规则页面，给出合并建议。 |

### 前文回改

| 场景 | 提示词 |
|------|--------|
| 修改前文 | 请修改第 X 章中【具体内容】，改为……。修改后列出受影响的后续章节和设定页面，并同步更新。 |
| 检查回改影响 | 如果把第 X 章的【某个设定】改为……，会影响哪些后续章节和设定？请列影响范围，先不改。 |

### 审查

| 场景 | 提示词 |
|------|--------|
| 审查章节 | 请审查第 X 章：人物行为是否符合动机、时间线是否一致、情节因果是否成立、节奏是否有问题。 |
| 审查人物线 | 请审查【人物名】从第 X 章到第 Y 章的人物弧线，检查动机是否连贯、变化是否有铺垫。 |
| 审查伏笔 | 请审查所有伏笔的埋设、推进和回收情况，标出遗忘的伏笔。 |
| 审查 AIGC 痕迹 | 请对第 X 章执行原创性与 AIGC 痕迹质量检查，只检查模板化、空泛化、人物语言同质和缺少具体细节的问题，不做检测器规避改写。 |

## 五、核心规则速览

### 文件职责

| 文件 | 职责 |
|------|------|
| `AGENTS.md` | Codex 等 agent 的项目级行为规则 |
| `Claude.md` | Claude 工作流使用的项目级行为规则，规则内容应与 `AGENTS.md` 保持等价 |
| `docs/aigc-quality-control.md` | AIGC 检测手段研究摘要和原创性质量控制规则 |
| `llm-wiki/wiki/index.md` | 内容索引，写作/查询前必读 |
| `llm-wiki/wiki/book-spine.md` | 全书主线龙骨（压缩版） |
| `llm-wiki/wiki/outline.md` | 剧情总纲，串联章节组和整体脉络 |
| `novel/03_plot/chapters/chXXX-spine.md` | 每章剧情龙骨 |
| `llm-wiki/wiki/timeline.md` | 事件时间线 |
| `llm-wiki/wiki/character-states.md` | 人物当前状态账本 |
| `llm-wiki/wiki/relationship-states.md` | 人物关系状态账本 |
| `llm-wiki/wiki/foreshadowing-ledger.md` | 伏笔账本 |
| `llm-wiki/wiki/contradiction-flags.md` | 矛盾标记 |
| `llm-wiki/wiki/log.md` | 操作日志（只追加） |
| `llm-wiki/ingest-manifest.md` | 摄入清单 |
| `novel/05_manuscript/chXXX.md` | 章节正文 |

### 优先级

1. 系统与开发者指令
2. 用户当前请求
3. `AGENTS.md` 或 `Claude.md` 项目规则
4. `docs/` 中的方案和流程
5. `llm-wiki/` 设定和资料
6. `novel/` 正文、草稿和备份资料
7. memory 或历史会话

### 关键原则

- **所有设定必须落文件**：不依赖对话记忆。
- **日常资料只走 `llm-wiki/`**：源文件只用于证据回查或正文核对。
- **每章必须维护龙骨**：未完成同步不算章节完成。
- **正文优先**：设定、资料、大纲都服务正文。
- **原创性优先**：AIGC 痕迹检查只用于提升正文质量，不用于欺骗或规避检测器。
- **默认向后推进**：前文回改须先确认影响范围。
- **`raw/` 只读**：原始资源不得修改。

## 六、典型工作流示例

### 场景 A：全新开始

```text
你：我想写一本修仙小说，主角是个废柴弟子，意外获得上古传承。
    帮我填写 brief.md，然后规划前五章的大纲。

AI：填写 brief.md -> 生成或登记 raw/ 设定 -> 摄入 llm-wiki -> 生成前五章龙骨。

你：按第一章龙骨写正文，4000 字，开场要有反差感。

AI：写正文到 ch001.md。

你：同步 llm-wiki。

AI：同步龙骨、时间线、人物、伏笔、索引、日志。

你：继续写第二章。
```

### 场景 B：已有大纲，快速推进

```text
你：我已经把大纲文档放入 raw/。请摄入 raw/ 中的大纲，然后从第一章开始写。

AI：摄入 -> 生成龙骨 -> 写正文 -> 同步 -> 询问是否继续下一章。
```

### 场景 C：写到中途发现矛盾

```text
你：我发现第 8 章里主角说他不认识李某，但第 3 章里两人已经见过面了。
    帮我检查一下。

AI：检查 wiki -> 确认矛盾 -> 列出影响范围 -> 提出修正方案。

你：按方案 A 改，改完后同步。

AI：修改第 8 章正文 -> 更新所有受影响的 wiki 页面 -> 记录日志。
```

### 场景 D：隔一段时间回来继续写

```text
你：我上次写到第 15 章，帮我回顾一下当前进度。

AI：读取 book-spine.md、llm-wiki/wiki/outline.md、最新章节龙骨、log.md。
    当前主线在第 X 阶段，第 15 章结尾是……，未回收伏笔有 X 条，下一步应该……

你：继续写第 16 章。

AI：生成第 16 章龙骨 -> 确认 -> 写正文 -> 同步。
```

## 七、注意事项

1. **一章一龙骨**：不要跳过龙骨直接写正文，也不要写完正文再补龙骨。
2. **同步要及时**：正文完成后立即同步，不要攒着。
3. **不要一次塞太多**：AI 写作时只读取当前章节相关资料，不读全部文件。
4. **回改要谨慎**：修改前文前先确认影响范围，改完必须同步检查后续。
5. **口头确认的设定也要落文件**：对话中讨论确定的设定必须写入 `llm-wiki/`。
6. **定期健康检查**：每 5-10 章做一次 `llm-wiki` 健康检查，防止矛盾积累。
