# 章节龙骨目录

本目录保存每章剧情发展的简短龙骨。

章节龙骨由 `llm-wiki/wiki/outline.md` 总体大纲串联。单章龙骨记录单章变化；跨章节组的阶段推进、支线转折和节奏安排，应同步写入总体大纲。

章节龙骨用于回答三个问题：

1. 本章开始时，世界和人物处于什么状态。
2. 本章推进了什么。
3. 本章结束后，哪些状态发生了变化。

规则：

- 每章一个文件，命名为 `ch001-spine.md`、`ch002-spine.md`。
- 每章另有一个机器任务文件，命名为 `ch001-job.json`、`ch002-job.json`；它只保存本章显式输入路径、前章行号范围、正文目标和审稿比较资料。
- 写正文前先建立草案。
- 正文启动前用框架脚本校验任务并生成隔离写作封包；JSON 与龙骨不一致时停止写作。
- 写正文后按实际内容修正。
- 章节完成必须完成正文初稿、原创性与文本质量检查、章节龙骨修正和章后同步清单；细则以模板为准。
- 单章龙骨保持简短，建议 300-800 字；复杂章节最多 1200 字。

模板见 `_chapter-spine-template.md` 和 `_chapter-job-template.json`。

## 章节任务字段

任务文件使用 UTF-8 JSON。所有路径都是小说实例内的相对文件路径，不接受绝对路径、目录、`..`、符号链接越界或 `novelforge.json` 中声明的禁读位置。

| 字段 | 类型 | 用途 |
| --- | --- | --- |
| `schema_version` | 整数 `1` | 当前任务契约版本。 |
| `chapter` | 字符串 | 本章稳定编号，使用 `ch` 加至少三位数字，例如 `ch001`。该编号必须与 spine 和正文文件名一致。 |
| `spine` | 字符串路径 | 本章龙骨；封包器只抽取故事相关标题，不传同步和审查清单。 |
| `draft` | 字符串路径 | `novel/05_manuscript/` 下的正文目标。 |
| `chapter_sources` | 字符串路径数组 | 本章明确相关、可全文进入写作包的 UTF-8 文本；不得重复列入控制文件、全局正本、章节 spine、审稿原则或近章全文。 |
| `previous_excerpt` | `null` 或对象 | 对象包含 `novel/05_manuscript/` 内的 `path`，以及从 `1` 开始且闭区间的 `start_line`、`end_line`；原文件不得同时全文进入写作包。 |
| `recent_chapters` | 字符串路径数组 | 最多三份来自正文或章节龙骨的材料，只在独立审稿任务中用于结构比较，不进入写作任务。 |
